# 요구사항정의서

---

## MVP1

취업 정보 공유 게시판 + 스터디 모집 기능을 갖춘. **취준생 커뮤니티 SNS**를 구현하고, 팀 협업 루틴(Git·PR·데모)을 심화한다.

### 1. 계정/역할 정의

| 역할 | 설명 | 권한 |
| --- | --- | --- |
| 비로그인 | - | 정보공유게시판 조회, 스터디 목록 조회, 전문가 목록 조회(프로필만, 상담 내역은 비공개) 가능 |
| 일반(USER) | 기본 회원 | Q&A 게시판 CRUD, 스터디 가입(미구독 시 개설+참여 합산 최대 2개, 구독 시 무제한), 구독 결제 가능 |
| 전문가(EXPERT) | 유료 서비스 제공자 | 경력 N년 이상을 기준으로 ADMIN이 승인. 구독자가 개설한 1:1 문의 스레드에 답변 메시지 작성 |
| 어드민(ADMIN) | 관리자 | 전체 게시판 관리, 유저 관리, 전문가 승인/거절 관리 |

### 2. 필수 기능 (MVP)

#### 회원/인증

| ID | 기능 | 설명 | 완료 기준 |
| --- | --- | --- | --- |
| F-01 | 회원가입 | 이름·이메일(email 형식)·비밀번호(최소 8자)·닉네임 | 비밀번호 암호화 저장, 201 |
| F-02 | 로그인(JWT) | 토큰 발급 | 로그인 성공 시 JWT accessToken 발급 및 refreshToken 기반 재발급 가능 |
| F-03 | 소셜 로그인(Kakao/Google/Naver) | 카카오, 구글, 네이버 로그인 | 인증 후 JWT accessToken 발급(최초 로그인 시 자동 가입, `oauth_account`에 provider별 기록) |

| F-14 | 스터디 게시판 목록/상세 | 글 목록, 페이징, 카테고리, 키워드 검색 | page, size 파라미터 동작, 카테고리, 키워드 검색 |
| F-15 | 스터디 게시판 수정/삭제 | 게시글 작성자 본인만 수정/삭제 가능. ADMIN은 관리자 전용 기능을 통해 강제 삭제 가능 | 타인 수정/삭제 403 |
| F-16 | 스터디 게시판 댓글 등록 | 게시글에 댓글 1:N | 가입 완료된 멤버가 댓글 작성 가능, `StudyPostComment`로 저장 |
| F-17 | 스터디 게시판 댓글 수정/삭제 | 댓글 작성자 본인만 수정/삭제 가능. ADMIN은 관리자 전용 기능을 통해 강제 삭제 가능 | 타인 수정/삭제 403 |
| F-18 | 그룹 내 유저 관리 | 방장만 멤버 강제 탈퇴 처리 가능 | 방장 아닌 사용자 처리 시 403 |
| F-19 | 방장 위임 | 방장이 다른 멤버에게 방장 권한을 넘김 | 위임 대상은 가입 완료 멤버만 가능, 위임 즉시 leader_id 변경 |
| F-20 | 스터디 탈퇴 처리 | 하나의 탈퇴 API로 일반 멤버와 방장을 함께 처리한다. 방장이 스터디 탈퇴 시도 시 위임 여부 확인 | 일반 멤버는 즉시 탈퇴 가능 / 방장은 다른 멤버가 존재할 경우 방장 위임 후 탈퇴 가능 / 방장 1인 스터디는 위임 없이 탈퇴 가능하며 스터디 자동 삭제 / 방장이 위임 없이 탈퇴 시도할 경우 403 |

## MVP2

외부 API 연동과 **유료 구독(PortOne 실연동)** SNS를 **React + Spring Boot**로 구현하고, Docker로 실행 가능한 서비스를 만든다. 결제는 PortOne V2 빌링키 기반 정기결제(테스트 채널)로 구현한다.

### 1. 필수 기능 (MVP2)

#### 회원/인증

| ID | 기능 | 설명 | 완료 기준 |
| --- | --- | --- | --- |
| F-01 | 회원가입 | 이름·이메일·비밀번호(최소 8자)·닉네임·약관동의(필수) 입력. **이메일 인증 완료(F-39)** 와 **이용약관 동의**가 모두 확인되어야 가입 처리됨. 동일 이메일의 소셜 전용 계정이 이미 있으면 신규 생성 대신 그 계정에 비밀번호를 연결(F-41 참조) | 비밀번호 BCrypt 암호화 저장, 약관 동의 시각(terms_agree_at) 저장, 201 Created / 이메일 중복 409, 닉네임 중복 409, 이메일 미인증 400, 약관 미동의 400 |
| F-02 | 로그인(JWT) | username(email)·password로 로그인. 계정 상태 확인, 5회 연속 실패 시 10분간 계정 잠금 | 200 + accessToken(refreshToken은 HttpOnly 쿠키) / 비밀번호 불일치 401, 계정 없음 404, 정지 계정 403("정지된 계정입니다."), 탈퇴 계정 403("회원탈퇴한 사용자입니다."), 잠금 상태 403 |
| F-02-1 | 토큰 재발급 | refreshToken(쿠키)으로 accessToken 재발급 | 서명·만료 검증, 저장된 해시와 대조, 계정 상태 ACTIVE 확인 후 신규 토큰 발급(로테이션) / 토큰 무효 401, 정지·탈퇴 계정 403 |
| F-02-2 | 로그인 실패 횟수 제한(브루트포스 방어) | 로그인 5회 연속 실패 시 계정 10분간 잠금(F-02에 포함되어 동작하나, 별도 정책으로 명시) | 실패마다 카운트 증가, 5회 도달 시 잠금 및 리셋, 성공 시 초기화 |
| F-02-3 | 로그아웃 | 서버에 저장된 refreshToken 삭제 및 클라이언트 쿠키 만료 | 로그아웃되면서 refreshToken 무효화 200 |
| F-03 | 소셜 로그인 (Kakao/Google/Naver) | 소셜 인증 후 JWT 발급, 최초 로그인 시 자동 가입(oauth_account 기록). 동일 이메일의 일반 계정이 있으면 자동 연동(F-41 참조) | 200 + { accessToken }, refreshToken 쿠키 전달 / 소셜 토큰 무효 401, 정지·탈퇴 계정 403 |
| F-24 | 회원탈퇴 | 본인 계정 비밀번호 확인 후 탈퇴 처리(소셜 전용 계정은 검증 생략). 활성 구독 자동 취소, refreshToken 삭제. **탈퇴 시 콘텐츠 처리**: 일반 게시글/댓글은 삭제·숨김 없이 유지되고 작성자 정보만 "탈퇴한 사용자"로 자동 표기됨(User 익명화에 따라 자동 반영). 방장인 스터디(및 하위 스터디게시글·댓글)는 소프트 딜리트되어 노출되지 않고, 가입한 스터디는 멤버 자격만 제거됨 | 탈퇴 시 계정 비활성화(status=WITHDRAWN), name/nickname 익명화, refreshToken 삭제, 200 |
| F-39 | 이메일 인증 | 이메일로 6자리 인증 코드 발송·검증하는 공통 서비스. **F-01(회원가입)** 과 **F-40(비밀번호 재설정)** 에서 공통으로 사용됨 | 인증 코드 유효시간 5분, 초과 시 재발송 필요 / 재발송 30초 쿨다운, 10분당 5회 제한 / 인증 확인 시 기록은 즉시 소비(1회성)되어 재사용 불가 |
| F-40 | 비밀번호 재설정(이메일 인증 기반) | 로그인 화면 "비밀번호 찾기" → 이메일 인증(F-39 재사용) → 새 비밀번호 설정 | 인증 유효시간 5분, 인증 기록 1회성 소비 / 재설정 성공 시 새 비밀번호 저장, 기존 refreshToken 무효화 |
| F-41 | 일반 로그인·소셜 로그인 계정 통합 | **F-01, F-03에 걸친 공통 정책**: 동일 이메일 기준으로 일반 가입 계정과 소셜 로그인 계정을 양방향 자동 연동한다 | 이메일 일치 시 자동 연동(일반→소셜 방향은 이메일 인증 필요, 소셜→일반 방향은 provider의 이메일 검증을 신뢰). 연동 후 소셜/일반 로그인 모두 동일 계정 접근 가능. 비밀번호 없는 소셜 전용 계정은 F-01(회원가입 폼)로 재시도 시 비밀번호 연결됨 |
